# Docker 한 줄 설치: 배포 설계

사용자와 논의한 방향이며, 아래 배포 이미지와 설치 마법사는 아직 구현·공개 전입니다. 현재 0.2.1은 개인 서버에 배포된 내장 Tailscale 노트입니다.

## 목표 사용 흐름

```sh
docker run -d --name note --restart unless-stopped -p 8080:8080 -v note-data:/data ghcr.io/chelly1221/note:latest
```

1. 컨테이너 실행 후 브라우저로 서버의 8080 포트에 접속합니다.
2. 설치 확인 코드로 최초 설치 권한을 확인합니다. 먼저 접속한 임의 방문자가 소유자가 되는 방식은 사용하지 않습니다.
3. 기본 로컬 저장소 또는 NAS를 선택합니다. 연결·쓰기 권한을 검사하고 오류 해결 방법을 안내합니다.
4. 서버의 Tailscale 기기를 등록하고 소유자 계정을 지정합니다. 사용자가 공식 인증 화면에서 승인합니다.
5. 웹 HTTPS 주소와 백업 정책을 설정하고 최종 연결 검사를 수행합니다.
6. 완료 화면의 QR로 Android에 서버 정보를 전달합니다. QR에는 사용자 암호나 공유 인증 키를 담지 않습니다.
7. 다음 접속부터 노트 화면과 서버 관리 화면을 제공합니다. 설치 상태는 볼륨에 보존하고 실패한 단계부터 재개합니다.

## 구조 변경

- 노트 웹 화면과 Android는 클라이언트입니다. 서버 패키지는 웹 배포, 인증, 저장, 동기화 및 관리 API를 담당합니다.
- 현재 Go/WASM과 TypeScript에 고정된 서버 주소를 검증된 인스턴스 설정으로 바꿔야 합니다. 연결 대상과 저장소 식별자를 확인합니다.
- 설치 완료 후 초기 설치 API를 닫습니다. 관리 API는 소유자 인증을 요구합니다.
- 기본 로컬 볼륨은 바로 사용할 수 있게 합니다. NAS 연결은 자동화 가능한 범위와 호스트 설정이 필요한 범위를 구분합니다. Docker 소켓이나 privileged 권한을 기본으로 부여하지 않습니다.
- 일반 HTTP 원격 주소에서는 브라우저의 보안 API가 제한되므로, 노트 클라이언트 사용 전 HTTPS 설정을 마쳐야 합니다. 로컬 설치와 원격 서버 설치를 각각 안내합니다.
- 첫 관리 화면은 서버/NAS 상태, 용량, 최근 오류, 백업 생성·목록, 버전을 중심으로 만듭니다. 복원·저장소 변경은 영향 범위와 복구 경로를 보여줍니다.
- Tailscale 기기 승인은 공식 관리 화면을 이용합니다. 노트 관리 화면은 노트 서버 운영에 필요한 범위를 담당합니다.

## 배포 전 검증

빈 볼륨 설치, 중단 후 재개, 설정된 볼륨으로 재실행, 업데이트, 소유자 외 접근 거부, NAS 장애·복구, 백업 복원, 웹/Android 최초 연결을 확인해야 합니다. GHCR 이미지 빌드와 게시가 완료되기 전에는 위 명령을 실행 가능한 설치 안내로 제공하지 않습니다.
