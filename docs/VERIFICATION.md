# 노트 0.1.4 검증 기록

2026-09-10 웹과 Android 설치 파일을 제작하고 서버/NAS 연결을 검증했습니다.

배포 APK의 SHA-256은 `f118320a7f447f6c887c53fdadbdb1fc75195219ccfd712c2437dbaeaeae150c`이며 실제 다운로드 파일과 일치합니다. 기존 앱과 같은 인증서로 서명했고 업데이트 설치를 확인했습니다.

## 확인한 결과

- 자동 테스트 71개 통과: NAS 이력·복구·이미지 무결성, 수정 충돌과 중복 전송, IndexedDB 저장, 입력 중 화면 이동, 백업/복원, Tailscale 인증, 실시간 변경 알림.
- 다른 저장소의 로컬 인덱스를 연결한 경우 초기 요청과 모든 재시도를 계속 차단하는 회귀 검사를 추가했습니다.
- TypeScript 검사, 린트, 웹 빌드 및 Android 릴리스 빌드 통과.
- 공개 `note.3chan.kr`의 `/api/*`는 차단됩니다. 실제 API는 Tailscale Serve에서 허용 계정을 확인하며, 이전 앱 키·쿠키로는 접근할 수 없습니다.
- 웹의 제목·본문·체크리스트·태그는 별도 저장 동작 없이 유지됩니다. 입력 직후 목록 이동과 새로고침 후에도 내용이 남았습니다.
- 서로 다른 브라우저 저장 공간에서 양방향 수정 내용이 새로고침 없이 전달됐습니다.
- 노트의 Tailscale Serve 연결만 45초 중단했습니다. 기존 편집 화면에서는 입력 내용이 남았고 새 창은 인증 안내만 표시했습니다. 연결 복구 후 NAS 및 다른 저장 공간에 자동 반영됐습니다.
- 이미지 2장 첨부 직후 이동해도 모두 보존됐으며, 원본과 API 다운로드의 SHA-256이 일치했습니다. 잘못된 이미지가 포함된 묶음은 본문을 일부만 변경하지 않았습니다.
- 모바일 너비 320px/390px에서 제목 줄바꿈, 메뉴, 편집/미리보기, 체크박스와 폴더 동선을 확인했습니다.
- 실제 NAS 이력을 임시 인덱스로 재생하여 22개 문서를 파생 JSON과 전수 비교했습니다. 내용은 일치했고 운영 인덱스는 변경하지 않았습니다. 이후 검증용 노트 정리도 새 이력으로 남습니다.
- 최종 복구 코드로 현재 변경 이력 44개와 문서 23개를 다시 확인했고 모두 일치했습니다.
- Nextcloud Notes 원본 16개의 제목·본문·수정 시간 및 NAS 결과를 비교했습니다. 원본은 유지하며 NAS 공유의 `nextcloud-import-20260910`에 이전 자료를 보관합니다.
- WebMCP 검색·생성 도구, 잘못된 인자 거부, 잠금 상태에서 도구 제거를 확인했습니다.

## Android 검증 범위

서명된 APK 설치, 번들 포함, 공개 HTTPS 인증서 신뢰 및 공개 API 차단을 확인했습니다. Android 런타임 테스트는 2개 통과했고, Tailscale이 연결되지 않은 에뮬레이터의 전용 서버 인증 테스트 1개는 건너뛰었습니다. 실제 휴대폰의 Tailscale 연결과 키보드·편집 UI 직접 조작은 별도 확인이 필요합니다.

개별 Markdown/이미지 ZIP 및 전체 JSON 백업의 구성·검증·복원은 자동 테스트로 확인했습니다. Codex 내장 브라우저에서는 ZIP 다운로드 이벤트를 확인하지 못했습니다.

## 운영 점검 도구

`node scripts/verify-tailscale-live.mjs`는 연결된 개발 PC에서 공개 API 차단, Tailscale 인증, 가져온 노트 수와 검증 이미지 해시를 읽기 전용으로 확인합니다. 검증용 노트를 휴지통에 두어도 확인할 수 있습니다.

`scripts/verify-live.py`는 Tailscale이 연결된 앱 서버에서 실행합니다. 새 검증용 노트 1개를 만들어 중복 전송·충돌·휴지통·복원·변경 이력을 확인한 뒤 휴지통에 둡니다.

`scripts/verify-recovery.ts`는 운영 NAS를 읽고 `/tmp/note-recovery-*` 아래 별도 SQLite 인덱스를 생성하여 복구를 검증합니다. 검사가 끝나면 임시 인덱스를 지우며 노트 원문은 출력하지 않습니다.
