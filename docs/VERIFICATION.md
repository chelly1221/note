# 노트 검증 기록

## 0.2.10 · 알림 없는 백그라운드 동기화

2026-09-11. Vitest 94개, 타입 검사·웹·서버 빌드와 기존 키의 Android 서명 릴리스 빌드가 통과했다.

- Android 16에서 실제 배터리 최적화 상태 변경과 복귀 후 UI 갱신, 이미 허용된 설정의 중복 요청 방지, 예약 작업 중복 방지·로그아웃 취소·화면 없는 번들 JavaScript 실행을 확인했다. 오프라인 재실행에서도 저장된 노트가 먼저 열렸다.
- 휴대폰 1080×2400과 태블릿 1200×1920/density180·글자 배율 1.3에서 새 설정 화면을 검토했으며 독립 검토 결과는 `ship`이다. 작은 화면에서 기존 연결 버튼 줄도 줄바꿈하여 가로 넘침을 방지했다.
- 기존 note.service를 통해 배포했다. NAS storageReady, 비공개 API 200·공개 데이터 API 404를 확인했다. 웹 index·service worker·favicon과 다운로드 APK의 SHA-256이 로컬 빌드와 일치했다.
- 에뮬레이터에서는 합성 데이터와 오프라인 상태를 사용했다. 닫힌 앱의 인증된 내장 Tailscale → 원격 서버 전체 경로 및 제조사별 장기 절전 동작은 이번 검증에 포함되지 않는다. Android 예약은 지연될 수 있으며 강제 종료 후에는 다시 열어야 한다.

## 0.2.7 — 앱 안의 Tailscale 인증 창

Android에서는 Tailscale 인증 링크를 앱 위의 어두운 Custom Tab으로 엽니다. 웹 브라우저의 일반 링크 동작은 유지합니다. 네이티브 플러그인은 공식 Tailscale 기기 인증 URL과 관리자 기기 목록만 받으며, 페이지에는 노트의 네이티브 브리지나 저장소를 노출하지 않습니다. Android 최소 지원 버전(API 24)은 유지했습니다.

내장 Tailscale 상태가 `Running`이 된 뒤 해당 인증 창을 닫습니다. 기기 승인 대기·연결 시작 상태에서는 닫지 않습니다. 열리는 중에 인증이 완료되면 Android 호스트가 가려질 때까지 닫기를 보류하고, 기존 MainActivity로 돌아오면서 인증 창을 작업 스택에서 제거합니다. 사용자가 직접 창을 닫은 뒤에는 나중의 완료 알림으로 앱을 다시 띄우지 않습니다.

- TypeScript·린트·웹/서버/Android 릴리스 빌드 통과.
- 자동 테스트 85개 통과. 새 검사는 완료 상태에서 한 번만 닫기, 창을 여는 동안의 승인, 주소 제한, 열기 실패 후 재시도를 확인합니다.
- Android 16 계측 테스트 2개 통과: 네이티브 URL 제한, 실제 Chrome Custom Tab을 연 직후 닫고 동일한 앱 Activity로 돌아오기 및 작업 스택에 탭이 남지 않음.
- 창 생명주기 검사는 인증이 필요 없는 공개 페이지로 수행했습니다. Google/Tailscale 계정 입력과 새 기기 승인은 자동화하지 않았으며 실제 계정 재인증 전체 흐름은 별도 사용자 확인 범위입니다.
- APK `note-0.2.7.apk`: 10,534,883바이트, SHA-256 `2ebf2ec3b6ea552c275387ef1c1ab2652aa98ba3bab3b37f19ff222fef062415`.

구현 참고: [Android Custom Tabs](https://developer.android.com/develop/ui/views/layout/webapps/overview-of-android-custom-tabs), [Android 작업 스택](https://developer.android.com/guide/components/activities/tasks-and-back-stack).

## 0.2.5 — 휴대폰 웹 캐시 갱신

기존 웹은 완성된 오프라인 화면을 유지하다가 사용자가 업데이트를 선택하면 전환합니다. 이 동작은 유지하고, 7초 뒤 사라지던 알림 대신 로그인 전에도 표시되는 업데이트 배너를 추가했습니다. 탭에 다시 돌아오거나 네트워크가 복구되면 1분 간격 제한으로 새 버전을 확인하며 서비스 워커 등록 시 HTTP 캐시를 우회합니다.

`/update.html`은 이전 웹 캐시에서도 접근할 수 있는 독립 업데이트 페이지입니다. 최신 워커 설치·활성화를 기다린 뒤 노트를 다시 열며 CacheStorage, IndexedDB, 인증 저장소를 삭제하지 않습니다. 기존 편집 중인 탭은 워커 전환 시 저장 확인을 거친 후 새로고침합니다.

- TypeScript·린트·웹 및 서버 빌드 통과.
- PWA/서비스 워커 관련 7개 테스트 통과. 저장 실패 시 활성화·새로고침 중단, 알림 표시 영역과 독립된 업데이트 상태, 모바일 탭 복귀 시 재확인 및 중복 제한을 검증했습니다.
- 실제 도메인에서 이전 버전이 열린 상태로 `/update.html`의 버튼을 눌러 v0.2.5 진입, 기존 노트 표시와 NAS 연결·인증 유지를 확인했습니다.
- 서버 컨테이너 정상 실행 및 API 격리 검사 통과.
- 웹만 갱신했으며 다운로드는 기존 Android 0.2.4 APK를 계속 가리킵니다.

## 0.2.4 — 계정 인증부터 시작하는 연결 안내

웹·Android 공통 시작 화면에서 내장 연결의 인증 정보를 먼저 확인합니다. 미인증 기기에는 Tailscale 계정 인증 버튼을 주 동작으로 표시하고, 계정·기기 승인 후 서버의 사용자 확인과 노트 열기로 진행합니다. 별도 관리자 승인이 필요한 상태도 안내하며, 인증 링크는 사용자가 직접 엽니다. 기존 기기는 저장된 인증 정보로 자동 연결됩니다.

웹의 로그인 전 화면과 사이드바에 안드로이드 앱 다운로드를 추가했습니다. 설정의 기존 다운로드와 같은 주소를 사용하며 네이티브 앱에서는 이 링크를 표시하지 않습니다.

- 자동 테스트 78개 통과. 추가한 검사는 인증 대기 중 서버 접근 차단, 인증 실패·시간 초과 시 중단, 서버에서 거부된 계정의 노트 진입 차단을 확인합니다.
- TypeScript, 린트, 웹·서버·Android 릴리스 빌드 통과.
- 별도 localhost 저장 공간에서 미인증 상태의 1단계, 인증 버튼과 공식 로그인 호스트, 로그인 전 앱 다운로드를 실제 브라우저에서 확인했습니다. 새 테스트 계정/기기는 승인하지 않았습니다.
- 기존 Android 16 에뮬레이터에 업데이트 설치 후 재인증 없이 노트 목록과 NAS 연결을 확인했습니다.
- 다운로드 메뉴만 먼저 배포할 때 웹 컨테이너 단독 재생성이 systemd 서비스의 API 종료를 유발했습니다. 서비스 전체 재시작으로 복구했고, 최종 배포는 systemd를 통해 수행한 후 두 컨테이너와 API 격리를 검증했습니다.
- APK `note-0.2.4.apk`: 10,449,278바이트, SHA-256 `b97474c9134b20d27769e4e68609b93b1495da7b3617acd7e23b32d1ad48ee4f`. 서버 배포 파일과 일치합니다.

## 0.2.3 — 제목 목록과 브랜딩

노트 목록은 제목만 표시합니다. 본문 미리보기, 날짜, 폴더·태그, 첨부 수, 즐겨찾기 아이콘을 행에서 제거했습니다. 행은 최소 52px이며 긴 제목은 두 줄까지 표시하고 전체 제목은 버튼 이름과 툴팁으로 유지합니다. 선택 상태에는 진회색 배경, 테두리, 얇은 그라데이션 표시와 `aria-pressed`를 함께 적용합니다.

검색창 안내, 구역 제목, 하단 상태 문구의 대비를 높였습니다. 지정 색상으로 계산한 대비는 일반 제목 13.82:1, 목록 보조 문구 7.15:1, 검색 안내 6.61:1, 검색창 경계 3.25:1입니다. 이는 변경한 색 조합의 계산 결과이며 전체 접근성 인증을 뜻하지 않습니다. 새 노트 버튼 테두리와 선택 표시에는 브랜드 그라데이션을 사용하고 읽기 영역은 무채색으로 유지합니다.

홈 버튼의 Lucide Sparkles 형태를 웹 파비콘(SVG, 16/32px PNG, ICO), PWA 아이콘과 Android 런처·적응형 아이콘에 적용했습니다. 파비콘 URL에는 새 버전을 붙여 이전 캐시와 구분합니다.

- TypeScript, 린트, 웹·서버·서명된 Android 릴리스 빌드 통과.

- Android 16 에뮬레이터의 기존 앱에 업데이트 설치 후 제목 목록, 선택 표시, 새 노트 버튼과 어두운 시스템 영역을 화면에서 확인했습니다. NAS 연결은 유지됐습니다.

## Android 검증 범위

서명된 APK 설치, 번들 포함, 공개 HTTPS 인증서 신뢰 및 공개 API 차단을 확인했습니다. Android 런타임 테스트는 2개 통과했고, Tailscale이 연결되지 않은 에뮬레이터의 전용 서버 인증 테스트 1개는 건너뛰었습니다. 실제 휴대폰의 Tailscale 연결과 키보드·편집 UI 직접 조작은 별도 확인이 필요합니다.

개별 Markdown/이미지 ZIP 및 전체 JSON 백업의 구성·검증·복원은 자동 테스트로 확인했습니다. Codex 내장 브라우저에서는 ZIP 다운로드 이벤트를 확인하지 못했습니다.

## 운영 점검 도구

`node scripts/verify-tailscale-live.mjs`는 연결된 개발 PC에서 공개 API 차단, Tailscale 인증, 가져온 노트 수와 검증 이미지 해시를 읽기 전용으로 확인합니다. 검증용 노트를 휴지통에 두어도 확인할 수 있습니다.

`scripts/verify-live.py`는 Tailscale이 연결된 앱 서버에서 실행합니다. 새 검증용 노트 1개를 만들어 중복 전송·충돌·휴지통·복원·변경 이력을 확인한 뒤 휴지통에 둡니다.

`scripts/verify-recovery.ts`는 운영 NAS를 읽고 `/tmp/note-recovery-*` 아래 별도 SQLite 인덱스를 생성하여 복구를 검증합니다. 검사가 끝나면 임시 인덱스를 지우며 노트 원문은 출력하지 않습니다.
